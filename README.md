# 글쓴이 안내서

이 저장소는 `content/` 아래에 글을 기록하고 정적 사이트를 만드는 작은 사이트입니다. 글쓴이는
파일을 고친 뒤 실제 명령인 `python3 build.py`를 실행하고, 방문자는 만들어진 `docs/`의 페이지를
읽습니다.
아래 예시는 파일 이름과 경로까지 포함한 완전한 파일이므로 그대로 복사해 시작할 수 있습니다.

## 새 글 쓰기

새 글은 `content/posts/<id>.md`로 저장합니다. `<id>`는 파일 확장자를 뺀 이름이며, 영문
소문자와 숫자와 하이픈만 써야 합니다. 헤더와 본문 사이에는 빈 줄을 하나 둡니다.

헤더에는 다음 네 필드를 씁니다.

- `written`: UTC 시각을 `YYYY-MM-DDTHH:MM:SSZ` 모양으로 씁니다. 예를 들어
  `2026-09-23T14:00:00Z`입니다.
- `type`: `short`, `medium`, `long` 중 하나입니다. `short` 글에는 `title`을 쓰지
  않고, 제목이 필요한 중간 글과 긴 글에는 `title`을 씁니다.
- `title`: `medium` 또는 `long` 글의 제목입니다. 따옴표 없이 한 줄로 씁니다.
- `tags`: 선택 사항이며 태그를 쉼표로 나눕니다. 쉼표 주변의 공백은 자동으로 정리됩니다.

다음은 제목과 태그를 갖춘 중간 글의 완전한 예입니다.

```post content/posts/hello.md
written: 2026-09-23T14:00:00Z
type: medium
title: 첫 번째 기록
tags: 시작, 기록

여기서 글을 시작합니다. 이 글에는 다른 글로 이어지는 출발점이 있습니다.

### 작은 제목

**굵은 글씨**, *기울임*, `코드`를 쓸 수 있습니다.
```

본문은 일반 문단과 `#`, `##`, `###` 제목, `- `로 시작하는 목록, `> `로 시작하는
인용문, **굵게**, *기울임*, `인라인 코드`를 지원합니다. 줄을 나누어 문단을 만들고,
마크다운 문법의 기호를 필요한 자리에 그대로 씁니다.

이미지는 먼저 실제 파일을 `content/images/사진.jpg`처럼 넣은 다음 본문에
`![사진 설명](images/사진.jpg)`라고 씁니다. 경로는 반드시 `images/`로 시작해야 하며,
대체 글자는 방문자에게 이미지 설명으로 보입니다. 파일이 없거나 다른 경로를 쓰면 빌드
오류가 납니다.

제목이 없는 짧은 글은 아래처럼 쓸 수 있습니다.

```post content/posts/target.md
written: 2026-09-23T14:01:00Z
type: short

이 글은 링크가 가리킬 대상입니다.
```

## 링크 걸기

링크는 `content/links/<id>.json`에 저장합니다. 링크 파일의 최상위 필드는 `id`, `from`,
`anchor`, `to`, `events`이며, `from`과 `to`에는 글의 id를 씁니다. `anchor`는 출발 글
본문에 실제로 한 번만 나오는 문장 일부여야 합니다. 빌더는 그 글자에 `[n]` 표시를 붙여
도착 글로 연결합니다.

`events`는 시간순 사건 목록입니다. 첫 사건은 `created`여야 합니다. 처음 만든 링크의
사유는 `why`에 쓰고, 사유를 바꾸려면 같은 링크에 `reason-changed` 사건을 시간순으로
추가합니다. 사건마다 `at`은 UTC 시각, `action`은 `created`, `reason-changed`,
`removed` 중 하나, `why`는 그 사건의 사유입니다. 링크를 지우려면 마지막 사건으로
`removed`를 추가합니다. 파일을 지우지 않아도 되며, 마지막 사건이 `removed`이면
방문자에게 링크가 나타나지 않습니다.

다음은 사유를 한 번 바꾼, 아직 살아 있는 링크의 완전한 예입니다.

```link content/links/hello-target.json
{
  "id": "hello-target",
  "from": "hello",
  "anchor": "다른 글",
  "to": "target",
  "events": [
    {
      "at": "2026-09-23T14:02:00Z",
      "action": "created",
      "why": "관련된 글을 연결함"
    },
    {
      "at": "2026-09-23T14:03:00Z",
      "action": "reason-changed",
      "why": "독자가 다음 글을 이어서 읽도록 안내함"
    }
  ]
}
```

## 패치 붙이기

패치는 원문을 고치지 않고 방문자에게 보이는 결과를 바꾸는 기록입니다.
`content/patches/<id>.json`에 `id`, `post`, `at`, `why`, `op`, `anchor`를 씁니다.
`id`는 파일 이름의 확장자를 뺀 값과 같아야 하고, `post`는 바꿀 글의 id입니다.
`at`은 UTC 시각, `why`는 변경 이유, `anchor`는 현재 본문에 정확히 한 번 있는 글자입니다.

`op`에는 네 가지가 있습니다. `replace`는 `anchor`를 `text`로 바꾸고,
`insert-before`는 anchor 앞에 `text`를 넣으며, `insert-after`는 뒤에 넣습니다.
`delete`는 anchor를 지웁니다. `delete`에는 `text` 필드를 쓰지 않고, 나머지 세 연산에는
`text`를 반드시 씁니다. 패치는 `at`이 이른 것부터, 같은 시간이면 `id`의 글자순으로
적용되므로 뒤의 패치가 앞 패치가 만든 글자를 anchor로 삼을 수 있습니다.

다음은 `hello` 글의 `출발점`을 `안내점`으로 바꾸는 완전한 패치 예입니다.

```patch content/patches/hello-wording.json
{
  "id": "hello-wording",
  "post": "hello",
  "at": "2026-09-23T14:04:00Z",
  "why": "표현을 더 분명하게 고침",
  "op": "replace",
  "anchor": "출발점",
  "text": "안내점"
}
```

## 사이트 만들기 — 빌드

저장소 루트에서 다음 명령을 실행합니다.

```sh
python3 build.py
```

실행 명령 `python3 build.py`가 `content/`의 글, 링크, 패치를 읽어 방문자가 볼 정적 파일을
`docs/`에 새로 만듭니다. 만든 뒤에는
`docs/index.html`에서 목록을, `docs/p/<id>.html`에서
글 페이지를 확인합니다. `docs/`는 호스트가 제공하는 결과 디렉터리이므로 생성된 HTML을
직접 고치지 말고 원본인 `content/`나 이 안내서의 규칙에 맞는 입력 파일을 고칩니다.

빌드가 실패하면 명령의 표준 오류인 `stderr`를 먼저 봅니다. 오류는 파일 경로를 담은 한 줄로
나오므로 그 줄의 `content/...` 경로에 있는 파일을 열어 형식, 날짜, id, anchor,
이미지 파일의 존재를 확인합니다. 예를 들어 링크 anchor가 본문에 없거나 두 번 나오면
링크 파일 경로가 표시되고, 패치의 anchor가 현재 글에 없거나 여러 번 나오면 패치 파일
경로가 표시됩니다. 고친 뒤 저장소 루트에서 `python3 build.py`를 다시 실행하면 됩니다.

## 방문자에게 보이는 모습

방문자가 처음 보는 `docs/index.html`에는 모든 글이 유형별로 나뉘지
않고 작성 시각의 최신순으로 한 줄씩 나옵니다. 각 항목에는 유형 이름과 시각이 붙으며, 같은
시각이면 `<id>` 순입니다. 짧은 글은 적용된 본문 전체를 보여주고, 중간 글과 긴 글은 제목과
시각을 보여줍니다. 모든 항목은 해당 글 페이지로 가는 링크입니다.

제목이 없는 중간 글이나 긴 글은 제목 대신 적용된 본문의 첫 문단을 HTML로 만든 뒤 화면에
보이는 글자 중 앞 80자를 보여줍니다. 80자를 넘으면 `…`을 붙입니다. 마크다운 서식 기호와
HTML 태그는 글자 수에서 빼고 유니코드 문자 단위로 세며, 첫 문단이 이미지만으로 되어 있으면
이미지의 `alt` 설명을 사용합니다. 피드에 보이는 본문도 패치가 적용된 본문입니다.

패치가 하나 이상 있는 글 페이지에는
기본으로 꺼진 `패치 보기` 토글 버튼이 있습니다. 버튼을 켜면 패치가 바꾸거나 넣은 영역에
테두리(아웃라인)가 표시되고, 지운 자리에도 작은 표시가 남습니다. 표시된 영역에 마우스를
올리면 그 자리에 적용된 패치의 이력이 각 패치의 시각(독자 현지 시각), 사유, 종류, 이전
글자와 함께 보입니다. 버튼을 끄면 표시와 이력은 사라지고 패치가 적용된 본문만 보입니다.

한 패치의 영역은 그 패치가 넣은 글자입니다. `replace`와 `insert-before`, `insert-after`는
`text` 전체가 영역이고, `delete`는 지운 자리의 표시 하나입니다. 삭제 표시는 패치 보기를
끌 때는 자리를 차지하지 않습니다. 이후 패치가 그 영역의 일부를 다시 바꾸면 적용된 본문의
각 글자는 마지막으로 만든 패치의 영역에 속하고, 앞선 패치의 영역은 남은 글자만큼 줄어듭니다.
한 영역의 이력에는 그 영역의 글자를 만들거나 바꾼 패치가 시각 순으로 나오며, `replace`와
`delete`의 이전 글자는 anchor의 글자, `insert-*`의 이전 글자는 없음(“새로 넣음”)입니다.
